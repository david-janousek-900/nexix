# V7 serial packet line discipline (task 68)

Nexix adapts `usr/sys/dev/pk0.c`–`pk3.c`, `usr/sys/h/pk.h` and `pk.p`,
`usr/src/libc/gen/pkon.c`, and the packet linesw registration generated by
`usr/sys/conf/mkconf.c`. The source contracts are described by `man4/pk.4`,
`man2/pkon.2` and `man3/pkopen.3`. All reference inputs remain unchanged.
This is the V7 serial packet protocol; TCP/IP remains a 0.2.0 feature.
UUCP's separate user-space packet engine and its empty pkon/pkoff stubs are
owned by its command-port tasks, rather than this kernel discipline.

`kernel/v7/packet.c` implements six-byte SYN headers, header XOR and V7's
16-bit rotating data checksum, INITA/B/C negotiation, modulo-eight sequence
numbers, two-packet windows, RR acknowledgements, reject/retransmission,
short-packet length prefixes, zero-length EOF and CLOSE. Receive and send
packet sizes are negotiated independently. A receive acknowledgement is sent
only after the application consumes the whole packet; duplicates cannot
reappear as application bytes. Short reads retain the packet remainder.
Queued packets drain before remote-close EOF, and subsequent reads keep
returning zero. Writes to a disconnected link raise SIGPIPE and fail EPIPE.

The UART receives wire bytes directly into the packet parser before cooked,
raw or cbreak processing. Transmit frames enter an atomic 4 KiB queue drained
by TX interrupts; packet transmission does not poll with receive IRQs masked.
Queue congestion retains unsent frames for retry. Console output and UART
reconfiguration drain preceding queued bytes in order. Raw mode is required
before attaching; settings changes fail EBUSY while attached. Multiplexor
ports/connections use decoded packets, flow-control wakeups and EOF events.
Changing discipline invalidates blocked multiplexor operations, and direct
TTY readers cannot bypass a multiplexor's ownership.

`kernel/v7/packet_tty.c` replaces the PDP-11 buddy allocator and global packet
buffer pool with one lazily allocated, bounded page per line. Its registry has
eight slots, with two receive and two send buffers per slot. COM1 is currently
the only physical TTY; independent ports remain tasks 89–93. Sleeping operations
pin their binding until return, including failed open and concurrent disable.
Last terminal close drains outstanding output before CLOSE and page release.
A silent peer is bounded by ten retries (one second during startup, three
seconds for data, shutdown on the next expiration); sleeps are interruptible.
Queued CLOSE output gets up to one additional second to enter the UART queue.
Partial frames expire after two seconds. These use a dedicated PIT hook;
the general V7 timeout callback queue remains task 364.

## Public interface and source differences

Include `<sys/pk.h>` for `pkon(fd, size)`, `pkoff(fd)` and the original
`turnon(fd, size, window, mode)` helper. `pkon` accepts 32, 64 or 128 bytes;
`turnon` and direct ioctl accept powers of two from 32 through 512 and windows
of one or two. They return the negotiated outbound packet size. The peer's
receive size controls this result independently of our requested receive size.

The manual advertises 32–4096 bytes, but the supplied libc pkon limits requests
to 128, and the supplied kernel pkopen limits receive size to 512. Nexix follows
those implementation limits. It rejects zero, nonpowers of two, zero/oversized
windows, unsupported mode bits and nonzero reserved padding with EINVAL, instead
of retaining unchecked historical inputs. Pkon retains the historical
`bad packet size` stderr diagnostic. Mode bit 0 is accepted for source
compatibility; historical kernel printf debugging is not emitted on the wire.

The native `struct piocb` is 12 bytes: a 32-bit discipline selector `t`, signed
16-bit `psize`, `mode`, `state`, followed by byte `window` and zero `reserved`.
`TIOCSETD` with `t=1` reads and writes this full record and blocks for negotiation.
`DIOCGETP` copies a fully initialized record and returns its packet size;
`TIOCGETD` returns a four-byte selector. `TIOCSETD` with a four-byte zero selector
explicitly disables the discipline without closing the descriptor. Unknown
selectors fail ENXIO; normal-mode packet status also fails ENXIO. Failed startup
restores the ordinary discipline without leaking a page. No existing syscall
number or native ABI version changes.

The supplied libc pkoff **closes the descriptor**; Nexix preserves that behavior
and returns the close result. Duplicated descriptors and retained multiplexor
references keep the shared terminal attached until explicit disable or last
close. This differs from the manual's implication of a descriptor-preserving
pkoff operation. Malformed lengths, unsupported size codes and invalid checksums
are rejected before accessing buffers or releasing acknowledged output; private
PDP-11 packet/TTY pointers are never exposed as native public structures.

## Validation

Run `make test-packet`. Host tests exercise every supported size/window, sequence
wrap, full/short/EOF packets, CRC rejection, acknowledgement ownership,
duplicates, retries, malformed short lengths, a deterministic parser stress run,
UART backpressure, timeout and page/descriptor lifetime.
A register-model test exercises the production UART queue, and libc mocks check
validation, ioctl errors and pkoff close semantics. Header and inventory audits
verify the native record and exports.

The independent Python peer in `tools/packet_smoke.py` exchanges binary frames
through QEMU COM1 at 16 and 128 MiB. It damages a checksum, drops a frame,
requests retransmission, sends duplicate input and EOF, closes a live link,
reopens with different packet sizes, exercises a multiplexor port and last-close
output drain, then verifies all terminal descriptors/pages are released and the
ordinary boot acceptance sequence completes. This does not claim UUCP consumer
acceptance, large manual-only packet sizes or additional serial hardware.
