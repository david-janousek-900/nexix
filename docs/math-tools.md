# V7 mathematics and language tools

## dc (task 208)

The installed `/bin/dc` retains the V7 decimal base-100 arithmetic engine,
stack/register/array language, macros, scales, input/output bases, square roots,
file-to-stdin input and shell escapes. Active sources are in `user/dc`; the V7
reference remains unchanged. It uses native libc and does not depend on libm
or a host arithmetic library.

The native port uses signed digit bytes and full-width pointer slots. Allocation
keeps live storage until realloc succeeds; copies never read beyond the source
block. The original symbol-table sentinel overrun and stack/nesting bounds are
corrected. Integer logarithms avoid signed shifts and 32-bit long assumptions.
Shell command text is bounded and missing string terminators report failure.
Historic recoverable calculator errors retain their printed diagnostics.

`make test-dc` runs the retained engine under ASan/UBSan against 180 independently
computed integer operations and Decimal square-root fixtures, then executes the
installed command on disposable 16/128 MiB guests. Native fixtures cover decimal
fractions, exponentiation, bases, macros, register stacks, arrays through index
2047, input-file/stdin sequencing and failure paths. Existing working disks are
not test targets. Lines retain the historical 70-column continuation format.

## bc (task 209)

`/bin/bc` keeps the retained V7 yacc grammar and generates the dc language.
`-c`/`-d` emit that language; ordinary execution connects the parser to installed
dc and reports parser/backend failures. Input files precede standard input;
`-l` first loads `/usr/lib/lib.b`. That data is the separately recovered,
hash-pinned six-function library, installed unchanged from `user/v7/bc/lib.b`.
Tests exercise e, s, c, l, a and j against independent numerical values.

Semantic values and bundle entries use intptr_t, and bundle construction uses
native stdarg rather than reading past a formal parameter. Compiler strings are
printed as data. Constant, loop-depth, string and input-file limits are checked;
malformed input reports an error instead of generating executable diagnostics.
EOF is treated as a final newline, and parser errors stop compilation with a
nonzero status. The language retains V7 single-letter names, function/auto
syntax and its historical grammar conflicts; it is not modern GNU bc syntax.

`make test-bc` checks the real yacc/dc pipeline under sanitizers, recursive
functions, loops, arrays, large arithmetic, all six math functions and malformed
inputs, then repeats the installed behavior at 16/128 MiB. The guest also
regenerates the parser with installed yacc and compares every generated byte
against the bootstrap output from the same native yacc sources.

## factor (task 210)

`/bin/factor` re-expresses the retained PDP-11 assembly as native integer C.
It accepts positive integers below 2^56 exactly, prints a blank line followed
by each prime factor with five leading spaces, and repeats factors as often
as necessary. Trial division uses 2, 3 and a 6k±1 wheel with overflow-safe bounds.
No floating-point rounding or historical hardware emulator is involved.

The retained decimal converter ignores spaces and ends a number at another
character: `1 2` and `12suffix` both yield 12. Zero or a nonnumeric input at the
start ends the session. EOF and input errors are distinct; range/overflow errors
print `Ouch.` with failure status, and extra operands are rejected explicitly.
Sanitizer tests use an independent factorization oracle, the maximum valid
56-bit input and overflow cases. Native 16/128 MiB fixtures include repeated
factors, a prime, a large semiprime, 2^55, stdin and range rejection.

## primes (task 211)

`/bin/primes [start]` reads the same decimal start convention as factor and
prints ascending primes at or above a positive start below 2^56. With no operand
it reads stdin. Zero/nonnumeric starts end the command; overflow reports `Ouch.`.
Output is immediate, and a closed reader terminates the producer normally through
SIGPIPE. The generator stops at the documented 56-bit domain ceiling.

This is a native equivalent of the supplied PDP-11 assembly, with a constant-space
integer primality implementation rather than its floating-point sieve. Modular
multiplication avoids overflowing 64-bit products and needs no compiler 128-bit
runtime helpers. Testing the first twelve prime bases is deterministic throughout
the supported range: the smallest composite passing all twelve is above 2^64
([Sorenson and Webster, Theorem 1.1](https://arxiv.org/abs/1509.00864)).

Tests compare 20,000 classifications with an independent sieve, reject known
strong pseudoprimes and check the upper-domain prime against GNU factor as an
independent host oracle. Native fixtures at 16/128 MiB check streaming, stdin,
pipe-reader close/reaping, exact near-ceiling values and range errors.
